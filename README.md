# Snapline AutoText

Snapline AutoText 是面向 macOS 的非官方定制版：把截图、图片和复制的文字挂在屏幕顶部的晾衣绳上，需要时展开取用。

此项目基于 [mohabujubara/snapline v1.6.2](https://github.com/mohabujubara/snapline/tree/v1.6.2)，其设计与实现源自 [Tendedero](https://github.com/alejandrobujan/tendedero)。原项目说明保存在 [README.upstream.md](README.upstream.md)。本仓库保留上游 MIT 许可证与版权声明，详见 [LICENSE](LICENSE)。

开源仓库为 [w88856678-rgb/snapline-auto-text](https://github.com/w88856678-rgb/snapline-auto-text)。安装包可从 [Releases](https://github.com/w88856678-rgb/snapline-auto-text/releases/latest) 获取；仓库里的 GitHub Actions 只构建和测试，不自动创建 Release。

## macOS 定制功能 · 1.6.6

- **复制文字自动挂上**：普通 ⌘C 会生成文字便签，保留原始全文、换行和 emoji；可单独关闭文字捕获。
- **取回纯文字**：单击文字便签复制，再用 ⌘V 粘贴原文。拖出文字便签时也提供纯文本数据，不附带便签图片或文件 URL。纯文本传输格式已通过自动测试；真实跨应用拖拽尚未完成实机验证。
- **20 项混合容量**：图片和文字共享容量。分页保留卡片原大小，常见屏幕每页 7 项，20 项分为 7 / 7 / 6；每页数量会随屏幕宽度调整。新卡自动跳到所在页，重复复制已挂着的文字会找到原便签的页。
- **固定与恢复**：固定卡片不会被新捕获挤下；满架时淘汰最早且未固定的卡片，仅取下挂架项，不删除原图或便签文件。已有卡片全部固定时，可额外保留最新一项。重启保留固定状态、手动位置和便签全文。
- **默认自动隐藏**：平时收起；将鼠标停在屏幕顶部区域时展开，移开约 0.5 秒后收起。新复制内容短暂展示约 2.5 秒。首次启动提示约 6 秒后结束，不会因为已有卡片而常驻展开。菜单打开或拖动期间会保持可操作；设置中可另选“保持展开直到内容被使用”。
- **图片功能保留**：截图监视、图片剪贴板捕获、标注和 OCR 沿用上游；可设置是否显示在全屏应用上。

本次新增功能仅维护 `macos/`。仓库保留上游 Windows 源码与素材供参考，不提供 Windows 定制版，也不承诺 Windows 具有上述新增功能。

## 安装与使用

支持 **macOS 14 及以上**，安装包为 Apple Silicon / Intel universal 构建。当前构建使用 ad hoc 签名，尚未经过 Apple 公证；首次打开若被 macOS 拦截，请在“系统设置 → 隐私与安全性”中允许打开。

1. 打开 `Snapline-AutoText-1.6.6.dmg`，将 `Snapline.app` 拖入 Applications。
2. 启动后，在菜单栏确认“复制文字自动挂上 / Auto-hang copied text”已开启。
3. 在文档或网页中复制文字。需要取用时，将鼠标移到屏幕顶部区域，单击便签复制，再在目标应用中粘贴。
4. 多页时使用绳子上的翻页按钮。双击便签可以编辑全文；右键可以固定、复制文字或取下。

**Control + Option + T** 可显示或隐藏绳子；若已被其他应用占用，会尝试 **Control + Option + Shift + T**，以菜单显示为准。快捷键或菜单展开后同样会在鼠标移开、短暂预览结束后自动收起。

数据保存在本机 `~/Library/Application Support/Snapline`。普通复制的文字会写入本地便签；不需要捕获时可关闭文字捕获。应用跳过带系统通用 concealed / transient / autogenerated 标记的剪贴板项目，但无法保证识别所有敏感内容。启动或重新开启捕获不会补抓此前的剪贴板内容，复制应用自己的便签也不会重复捕获。

## 从源码构建

完整 Xcode 或 Command Line Tools 均可用于构建，打包脚本生成两种架构。以下命令从仓库根目录执行：

```bash
cd macos
VERSION=1.6.6 SIGN_IDENTITY=- bash scripts/make-dmg.sh
```

产物位于 `macos/build/`：`Snapline.app`、`Snapline-1.6.6.dmg` 和 `Snapline-1.6.6-mac.zip`。`SIGN_IDENTITY=-` 强制本地 ad hoc 签名；发布者若需要公证，应自行配置 Developer ID 与公证流程。

脚本会在默认 SDK 构建失败时尝试已安装的 macOS 26 SDK。需要指定 SDK 时，可通过 `SDKROOT` 传入其路径；不需要改源代码。

## 测试

完整 Xcode 环境使用标准 XCTest：

```bash
cd macos
swift test
```

只有 Command Line Tools、缺少 XCTest 的环境可使用 fallback runner。它链接真实应用 Debug 对象，执行与 XCTest 相同的测试方法，不启动应用；测试使用独立剪贴板、临时文件和只读设置保护。

```bash
cd macos
swift build -c debug --triple "$(uname -m)-apple-macosx14.0"
python3 Tests/Standalone/run.py --build-root .build
```

若构建需要指定兼容 SDK，应为构建和 runner 使用相同的 `SDKROOT`。

1.6.6 本地 Debug 与 standalone 验证通过 **42 个测试、507 个检查，0 个失败**。测试覆盖文字内容与 RTF、剪贴板开关、便签全文、图片管线、纯文字传输格式、容量分页布局、固定与位置恢复，以及悬停展开与自动隐藏规则。

已完成 TextEdit 的实际 ⌘C 自动挂便签与单击便签后 ⌘V 粘贴纯文字。隔离 UI 中确认 20 项的第一页显示 7 张卡片及 1/3 页码，首次启动提示约 6 秒后绳子与悬浮窗口均收起。跨应用拖拽的 UI 自动化工具返回 `AXError.notImplemented`，不能据此宣称实机拖拽成功。

## CI 与发布范围

`.github/workflows/release.yml` 在 main 分支推送和针对 main 的 Pull Request 上使用 macOS runner：先执行标准 `swift test`，再构建 universal 应用，并上传 DMG/ZIP 构建产物。应用内版本为 **1.6.6**；main 产物标记为 `1.6.6`，PR 产物标记为 `dev`，用于评审，不代表正式发布。

CI 仅有仓库读取权限，不构建 Windows、不在 tag 上触发发布，也不自动创建 GitHub Release。
